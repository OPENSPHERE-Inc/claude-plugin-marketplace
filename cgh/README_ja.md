# cgh

*[English README](README.md)*

[`creview`](../creview/README_ja.md) を土台にした GitHub プルリクエストのワークフローです。
すべてのスキルがプルリクエスト URL を受け取ります。内容を確認して投稿を指示するまで、GitHub には
何も送りません。このプラグインは承認、マージ、push、スレッドの解決を行いません。

## 必要なもの

- `creview` プラグイン（Claude Code が依存関係として `cgh` と一緒にインストールします）と、その
  プルリクエスト機能に必要なもの: 認証済みの GitHub CLI（`gh`）、Git 2.41 以降、プルリクエストの
  リポジトリをリモートに持つクローン。
- オープン状態のプルリクエスト。
- リポジトリルートで開始したセッション。

## スキル

| コマンド | 目的 | オプション |
|---------|---------|---------|
| `/cgh:review` | プルリクエストをレビューし、トリアージ済みの指摘を投稿する。 | `--adversarial` |
| `/cgh:gate` | セルフレビュー済みのプルリクエストがマージできるかを判定し、PASS / BLOCK を投稿する。 | `--adversarial` |
| `/cgh:respond` | プルリクエストのレビューが求める修正を行い、返信する。 | `--no-confirm` |
| `/cgh:resolve` | `/cgh:review` が投稿した指摘を検証し、結果を返信する。 | |

### `/cgh:review`

`/creview:start` と `/creview:triage` を実行し、投稿内容を示して、指示を受けて投稿します。

- **イベント**: 投稿する指摘に Critical または Major があれば Request Changes、なければ Comment。
  LGTM の判定は行いません。
- **内容**: 各コメントは指摘 ID（`C-1`、`M-1`、`mi-1`）、指摘内容、見積の推奨を含みます。コスト、
  シグナル、レビューエージェントは含みません。
- **デフォルトで投稿するもの**: Will Fix とトリアージされた指摘。見積が Downgrade とした Critical /
  Major も、問題がコードに残るので含みます。
  - Info、Won't Fix、Downgrade された Minor は、指示がない限り投稿しません。プレビューに理由とともに
    一覧されます。
- **投稿先**:

| 指摘の場所 | 投稿先 |
|------------------------|---------------|
| 差分内の行 | インラインコメント |
| 差分外の行で、ファイルは差分内 | ファイルレベルコメント |
| 差分外のファイル、またはファイルなし | レビュー本文 |

### `/cgh:gate`

すでにセルフレビューされたコード向けのマージゲートです。見るのは、壊れたコード、既存の挙動の
リグレッション、記録する issue のない残余（コードの `TODO`、PR 本文の未完了項目、約束された
フォローアップ）だけです。あった方がよい程度のテスト、リファクタリング、スタイルは指摘しません。
issue やプルリクエストを挙げている残余は記録済みとみなします。観点は
[rules/gate-focus.md](rules/gate-focus.md) にあります。

- **BLOCK**（Request Changes）: 投稿する指摘、または未検証の前回までのゲート指摘に Critical / Major が
  ある、もしくはプルリクエストにマージコンフリクトがある。
- **PASS**（Comment）: それ以外。PASS は承認ではありません。

判定はレビュー本文に記載し、指摘は `/cgh:review` と同じように投稿します。

修正後、パスするまで繰り返し実行します。2 回目以降は、前回までのゲート指摘を現在のヘッドで
`/creview:resolve` により検証してレビュー本文で報告し、プルリクエスト全体を再度レビューします。修正
せずに受け入れる指摘は、スキルに取り下げを指示します。

### `/cgh:respond`

プルリクエストのコメントに `/creview:triage` を実行して結果を示し、確認を待ちます。その後
`/creview:respond --commit` を実行し、push を依頼します。push の後、コメントごとに 1 件、対応内容と
コミット、または変更しなかった理由を記した返信をドラフトします。内容を示し、指示を受けて投稿します。

- 確認の際に、指摘を修正の対象から外せます。その返信には、伝えた理由が記されます。修正するものが
  残っていなければ停止しません。
- `--no-confirm` を指定すると、停止せずにトリアージから修正へ進みます。返信は指定の有無によらず
  指示を待ちます。
- レビュー本文や issue コメント由来の指摘への返信は、作者へのメンション付きの issue コメントになります。
- `post` は、プルリクエストが修正コミットを含むまで返信を送りません。リベースするとハッシュが変わるので、
  そのまま push してください。
- 対応されなかった指摘には返信しません。ドラフト担当がコメントを特定できなかった指摘にも返信せず、
  一覧で報告します。
- `/creview:respond` はプルリクエストのコードをビルドしテストします。信頼できないプルリクエストについては
  [creview README](../creview/README_ja.md) の警告を参照してください。

### `/cgh:resolve`

自分のアカウントで `/cgh:review` が投稿した指摘を `/creview:resolve` で検証し、返信を示して、指示を
受けて投稿します。各返信は確認したコミットを示します。コードが指摘の推奨どおりの修正なら、詳細は省きます。

## 状態の保持

状態はプルリクエスト上にあるので、後の実行は前の実行のローカルファイルを必要としません。

- 投稿した指摘は ID と場所を持つ隠しマーカーを、検証は完了した ID を持つマーカーを含みます。有効なのは
  自分のコメント内のマーカーだけです。
- `/cgh:gate` と `/cgh:resolve` が読み戻すのはマーカー付きの指摘だけです: 手書きのコメントは確認しません。
  レビューを dismiss すると、その指摘は対象外になります。
- 指摘 ID は前回までの続きから採番するので、プルリクエスト内で一意です。そのためプルリクエスト上の ID が
  ローカルのレビュードキュメントの ID と異なることがあります。

## 制限事項

- レビューから投稿までの間にプルリクエストが進むと、`post` は拒否するのでスキルを再実行します: 指摘の行番号は
  レビューしたヘッドのものです。
- `/cgh:gate` と `/cgh:resolve` は、前回までの指摘を確認する必要があるときに、HEAD がプルリクエストにない
  コミットを持つ、またはヘッド上に未コミットの変更があると停止します: 結果がプルリクエストにないコードの
  説明になるためです。
- GitHub は自分のプルリクエストへの Request Changes を拒否するので、その場合は Comment で送ります。
  `/cgh:gate` の判定はレビュー本文に残ります。
- GitHub ではプルリクエストごとに保留中のレビューは 1 ユーザー 1 件です。先に送信または破棄してください。
- コメントの文面はプルリクエストを読んだレビュアーに由来します。スクリプトが `@` メンションをコードとして
  囲み HTML コメントをエスケープしますが、投稿前にプレビューを読んでください。
