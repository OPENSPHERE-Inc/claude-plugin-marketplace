# コミット計画ルール

起点 B から対象 T までに変わった各パスを、B の上に順に積むコミットのどれか 1 つに割り当てる計画を書く。B と T、`commit-plan.py` に渡す引数、`{{plugin_root}}`・`{{main_root}}`・`{{target_dir}}` の値は、本ルールを Read させたテンプレートかスキルが与える。

## 分け方

- 1 コミットは 1 つの論理的な変更とし、単独でレビューも取り消しもできるまとまりにする。
- コードとそのテストは同じコミットに入れる。
- プロジェクトが一緒に変えることを求めるファイルは同じコミットに入れる。例: プロジェクトの規約が定める翻訳の対やバイト同一のコピー。
- レビューで直した内容は、直された変更のコミットに含める。
- 変更が小さく目的が 1 つなら 1 コミットでよい。ファイルごとに 1 コミットにはしない。
- 依存の順に並べ、参照される側を、参照する側と同じかそれより前のコミットに入れる。中間コミットはビルドもテストもされない。
- 各パスは、それが入るコミットで T の内容になる。スクリプトは 1 ファイルの変更を分けられないので、複数の論理的な変更にかかわるファイルは、そのうち 1 つのコミットに入れる。
- `paths` の出力の `together` の各組は、同じコミットに入れる。

## メッセージ

- 言語と書式は、B までの `git log` に合わせる。
- `CLAUDE.md`、`AGENTS.md`、`.claude/rules/` などにプロジェクトのコミットの規約があれば従う。`.claude/rules/` は、`{{main_root}}` が `(none)` でなければそれを基準に、そうでなければ `{{target_dir}}` を基準に解決する。
- 規約がなければ、コードが何をするようになったかを述べる簡潔な 1 行にする。
- 指摘 ID、ワークフローの工程名（例: レビュー対応、差し戻し）、規約が求めないトレイラーを含めない。

## 計画ファイル

- レコードファイルとし、1 行を 1 コミットとして積む順に並べる。`{{plugin_root}}/rules/teammate.md` § ツール の、`.jsonl` ファイルを 1 つのオブジェクトとして 1 行で書く規則は、このファイルには適用しない。
- 各行は、`message` と `paths` のちょうど 2 つのキーを持つ JSON オブジェクトとする。
- `message`: 1 行目（件名）に空白以外の文字を含む文字列。複数行のメッセージは JSON 文字列の中の `\n` で表し、1 つの値を複数の行にまたがせない。
- `paths`: 空でない配列で、各要素は `commit-plan.py paths` が出力したとおりのリポジトリ相対パス。
- 計画全体で、`paths` の出力が挙げた各パスがちょうど 1 回現れ、それ以外のパスは現れない。

```
{"message": "Validate the input of the parser", "paths": ["src/parser.py", "tests/test_parser.py"]}
{"message": "Document the parser options", "paths": ["README.md"]}
```

## ツール

- `python3 {{plugin_root}}/scripts/commit-plan.py paths {B と T の引数}` で、割り当てるパスとその `status`、同じコミットに入れるパスの組 `together` を得る。
- `python3 {{plugin_root}}/scripts/commit-plan.py check {同じ引数} --plan {計画ファイル}` が合格する（終了コード 0 で `ok` が true）まで計画を直す。不合格の `errors` は、原因の行番号とパスを示す。
- 終了コード 2 は、コマンドラインの使い方の誤りである。コマンドを直す。
- それ以外の、`errors` のない失敗は計画が原因ではない。繰り返さない。`check` が失敗した場合は書いた計画ファイルをそのまま残し、`paths` が失敗した場合は計画ファイルを書かない。どちらの場合も、その `error` を報告に含める。
- 差分の本文をすべて読む必要はない。パスの一覧、設計ドキュメント、既存のコミットメッセージで分け方が決まるなら、それで計画してよい。
- 計画者は、ステージ、コミット、ref の変更をせず、`commit-plan.py` の `build` と `commit` を実行しない。
