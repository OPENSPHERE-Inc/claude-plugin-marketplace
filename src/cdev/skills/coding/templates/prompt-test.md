この実行で変更された AI 向けプロンプトファイルのそれぞれが、過不足・誤解なく解釈されるかをテストする。プロンプトは編集せず、書き込むのは `{{output_path}}` のみとする。

入力: タスク `{{task}}`、設計セクション `{{design_paths}}`、作業ツリー差分 `{{diff_path}}`（`fetch-diff.sh` 出力）、試行番号 `{{attempt_num}}`（情報のみ）。

手順:

1. `{{diff_path}}` から、この実行で作成・変更されたファイルのうち `{{plugin_root}}/rules/prompt.md` が定める AI 向けプロンプトに当たるものを列挙する。1 件もない場合は `{{output_path}}` に `{"pass": true, "files": []}` を書いて報告する。
2. 各ファイルについて、そのファイルと設計セクションからチェック項目を作成する。各項目は「このプロンプトを読んだエージェントは状況 X でどうすべきか」という質問形式とする（例: 入力が省略した値の決め方、ステップが失敗した時のフォールバック、ステップ間の入出力の流れ、各分岐の閾値）。プロンプトの入力仕様・各ステップ・各分岐条件・出力仕様をカバーする。
3. 各ファイルについて、Agent ツールでテスト担当を起動する（`general-purpose`、フォアグラウンド、name なし。複数ファイルのテスト担当は並列に起動する）。テスト担当はこの実行の文脈を持ってはならないため、ファイルごと・試行ごとに新たに起動し、teammate は使わない。プロンプト:

```
プロンプト解釈テスト担当。{prompt_path} を Read し、以下の各チェック項目に、そのプロンプトと、プロンプトが読み手に Read を指示するファイルから読み取れる情報のみで 1〜2 文で回答する。外部知識や推測は使わない。それらのファイルが使うパスのプレースホルダは次の値で解決する: {placeholder_values}。プロンプトから読み取れない / 曖昧 / 矛盾する項目は unclear として理由を 1 文添えて報告する。修正提案や編集はしない。

チェック項目:
1. {項目 1}
2. {項目 2}
...

戻り値: {pass, unclear_items: [{item, reason}]}（unclear_items が空配列なら pass: true）
```

   `{prompt_path}` は `{{target_dir}}` にファイルのパスを連結したもの。`{placeholder_values}` は、そのファイルと、そこが指すファイルが使うパスのプレースホルダそれぞれを、`{{target_dir}}` 内で指すパスに対応づけたもの。プラグインルートは、そのファイルが属するプラグインのディレクトリ（その `.claude-plugin/plugin.json` を持つディレクトリ）を指す。パスを特定できないプレースホルダは除き、残るものがなければ `(none)` と書く。

4. `{{output_path}}` を Write する。最上位の `pass` は全ファイルが pass のとき true、`item` / `reason` は {{doc_lang}} で記述する:

```
{"pass": <bool>, "files": [{"path": <string>, "pass": <bool>, "unclear_items": [{"item": <string>, "reason": <string>}]}]}
```

リーダー（`SendMessage` の `to: "main"`）へ完了を 1 行で報告する: テストしたファイル数と、unclear 項目があったファイル数。
