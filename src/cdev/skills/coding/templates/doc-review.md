`{{producer}}` が生成したドキュメントをレビューし、reviewer としてセルを resolve する（`{{plugin_root}}/rules/teammate.md` § レビューセル を参照）。最大 `{{review_rounds}}` ラウンドまで。

タスク: `{{task}}`
設計セクション（意図する変更）: `{{design_paths}}` の全ファイルを Read する。
この実行の変更: `{{diff_path}}`
Producer: `{{producer}}` | セルタスク: `{{cell_task}}`
Producer のスコープ: `{{assigned_scope}}`（スコープがファイルを持つとは、そのファイルか上位のディレクトリを挙げていることを指す）

producer が準備完了を通知したら、準備完了メッセージに記録された乖離を受け取り、そこに列挙されたファイルを Read し、それぞれでこの実行が変えた箇所を読み取り専用の `git diff HEAD -- {path}` で確かめる。`HEAD` にないファイルは全体をこの実行の変更とする。producer のスコープにあるほかのドキュメントファイル（`{{plugin_root}}/rules/teammate.md` § ドキュメントファイル の定義による）も、以下の判定に要る範囲で Glob / Grep / Read する。次を判定する:

- 変更したファイルがコードについて述べること — 挙動、インターフェース、オプション、既定値、パス、要件、例 — が、`{{target_dir}}` にあるコードの現状（`{{diff_path}}` にあるこの実行の変更を含む）と整合しているか。コードそのものを読んで判定する。
- この実行のコード変更が、producer のスコープにあるドキュメントファイル（変更したものもしていないものも）のうち producer が変えずに残した記述を誤りにしていないか。
- 設計が producer のスコープに求めるドキュメント変更がそろっているか。
- 変更したファイル同士が矛盾しないか。
- それらがプロジェクトのドキュメント規約と `{{plugin_root}}/rules/document.md` に従っているか。
- producer が記録した各乖離が成り立つか。つまり、コードがその乖離の述べるとおりに動き、設計やタスクがそれと異なるか。

`{{plugin_root}}/rules/teammate.md` § レビューセル の判断の優先順位にあるドキュメントセルの規則に従い、設計やタスクと食い違うコードに従った記述、および、述べるべきものをコードが持たないために producer が書かなかった、設計が求めるドキュメント変更は、producer がその乖離を記録していれば指摘にしない。記録していなければ、修正方針を乖離の記録とする Major の指摘にし、ドキュメントを変える修正方針にはしない。この実行が変えておらず、誤りにもしていない記述は範囲外とし、挙げても Info とする。ツール使用は Read / Glob / Grep / Bash(grep/ls/find) と、producer のファイルへのこの実行の変更か、ターニングポイントの内容を取るドキュメント変更について設計セクションが記すコミットでのファイルの内容を読むための読み取り専用の `git log` / `git show` / `git diff` に限定する。一切編集しない。

重大度ラベル: Critical（読み手が頼る記述がコードと矛盾する）/ Major（設計が求めるドキュメント変更の欠落、設計やタスクと食い違うコードに従った記述で乖離が記録されていないもの、成り立たない記録済みの乖離（修正方針は記録の訂正か取り下げ）、読み手を誤った使い方に導く記述、レンダリングを壊す記法）/ Minor（読み手を誤らせない文言・体裁）/ Info（参考）。対応が必要 = Critical / Major。

セル `{{cell_task}}` についてセルプロトコルを回す: 対応が必要な所見を `file:line` と問題内容・推奨修正方向として `{{producer}}` に DM し（`line` はファイルを Read して得た実際の行番号。文面は {{doc_lang}} で、重大度ラベルはそのまま）、重大度別の件数を 1 行（`Critical N / Major N / Minor N / Info N`）でリーダーへ報告する。
