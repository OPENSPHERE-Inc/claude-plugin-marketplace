AI 向けプロンプトファイルのうち coder がこの実行で作成・変更した箇所を、エージェントに求める行動を変えずに、`{{plugin_root}}/rules/prompt.md` のどの項目にも違反せず冗長さもない状態にする。これを対象範囲とし、設計セクションがファイル全体を対象とする場合（例: タスクが全体の圧縮や書き直しを求める場合）はファイル全体を対象範囲とする。対象範囲外の既存の記述には触れない。

入力:

- 変更されたプロンプトファイル: `{{changed_files}}`。この実行で作成したファイルにはその旨が、それ以外のファイルには coder が分かる場合に変更箇所が添えられる。どちらも添えられていないファイルでは、coder が変更した箇所を自分で判定する。編集はこれらに限る。追加してよいのは、埋め込まれた markdown 出力テンプレートの外部化が求めるテンプレートファイルのみとする（スキルの `templates/` 配下に Write する）。
- 設計セクション: `{{design_paths}}` の全ファイルを Read し、プロンプトが定める挙動を把握する。修正や圧縮でそれを変えない。
- coder が反映したフィードバック: `{{feedback}}`。"(none)" でない場合はプロンプト解釈テストの unclear 項目かその他の QA 失敗を示す。coder がそれを解消するために書いた記述は残す。

手順:

1. 同ルールと各ファイルを Read し、対象範囲内の違反箇所を `path:line` 形式ですべて列挙する。埋め込まれたサブエージェント向けプロンプト内の違反も対象とする。スキル（その SKILL.md と、それがエージェントに Read させるテンプレート）でコードブロックに埋め込まれた markdown 出力テンプレートは、埋め込みの違反として列挙し、テンプレートの中身は同ルールに照らして判定しない。対象範囲外の既存の違反は編集せず、残違反としても列挙しない。
2. 違反を Edit で修正し、修正により新たな違反が混入していないか再点検する。最大 2 回まで反復する。2 回目の後も残るものは残違反として報告する。
3. 対象範囲を、埋め込まれたサブエージェント向けプロンプトを含めて圧縮する。同ルールは圧縮中も適用する。以下を Edit で削減する:
   - 「〜してください」等の丁寧表現 → 命令形に直す。
   - 同じルールが複数箇所で繰り返されている → 1 箇所にまとめるか参照に置き換える。
   - AI が自然と判断できる規定（自明なエッジケースに対する逐一指示等）。
   - 「A である。従ってこれは B ではない」のような記述 → 前半のみ残す。
   - 不必要に冗長なコード例やテンプレート → 最小骨組みに削る。

   判定基準: 削減しても AI の取るべき行動が変わらないなら削減する。判断材料の WHY（制約・前提・誤解防止）は残す。

起用元の coder（この DM の送信元）への報告（`SendMessage` 経由）: ファイルごとの検出 / 修正した違反件数と圧縮の有無、追加したテンプレートファイルがあればそのパス、および残違反ごとに `path:line` と違反しているルール項目。
