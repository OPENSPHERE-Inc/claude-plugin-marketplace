# コードレビュールール

コードレビューを行う際は、以下のルールに従うこと。

- **レビューの目的はコード品質の向上であり、コメントの言葉尻の精度ではない。** 実際のバグ・リスク・不明瞭なコードを指摘すること。あらゆる技術的ニュアンスを網羅するために段落コメントへの書き換えを要求しないこと。
- **コメント関連の指摘は、既存コメントが保守者にバグを作らせる場合のみ。** それ以外の言い回しの微細な修正は Info 止まり、あるいは指摘しないこと。
- **長文弁明より FIXME を推奨する。** 実問題を将来の PR に先送りする場合は、長い「許容される理由」の段落コメントではなく、**短い `FIXME:` / `TODO:`** で問題点と対応方針だけを記す方向を推奨すること。
- **コード規約違反・バグ・文法エラーに該当しないリファクタリング提案は格下げする。** 単なる構造改善や命名整理などの提案は Info 止まり、あるいは指摘しないこと。
