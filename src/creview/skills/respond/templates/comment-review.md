修正サブエージェント（ステップ 2）が変更した各ファイルのコメントを `{{plugin_root}}/rules/comment.md` の規律に照らしてレビューし、違反があれば修正する。コードのロジックは変更しない。`{{plugin_root}}/rules/sub-agent.md` を Read し共通禁止事項を遵守する。

## 入力

- `{{diff_path}}`（`fetch-diff.sh` 出力。今回の修正差分）を Read し、追加・変更されたコメントの抽出元とする。
- `{{document_path}}`（レビュードキュメント）を Read し、各修正が対応した指摘の趣旨（Finding 本文・location・triage / estimate メタデータ）を把握する。コメント調整時に趣旨を棄損しないための参照。

## 実施内容

1. `{{plugin_root}}/rules/comment.md` を Read。
2. `{{diff_path}}` に含まれる各ファイルから、追加・変更されたコメント行を抽出する。コメント記号は言語別（`//` / `#` / `/* */` / `<!-- -->` 等）。
3. 全ファイルで追加・変更コメントが 1 件もない場合: 何もせず手順 6 に進む（`fix_count: 0`）。
4. 追加・変更された `FIXME:` / `TODO:` はすべて根拠を確認する。コード内のこの注記は「問題と方針を記録済みの先送り」として、その箇所をレビュー対象から外す根拠として恒久的に効くため、次のいずれかに該当するものだけを許容する。
   - `{{document_path}}` で `Estimate:` が 🚧 Alternative の指摘が挿入を指示した FIXME である（file:line と内容で対応付け）。
   - 対象プロジェクトで既に確定済みの設計判断（CLAUDE.md、ADR、同一箇所の既存コメント）を記録したものである。
   いずれにも該当しないものは Edit で削除する。修正サブエージェントが修正中に気付いた残余の穴を自分の判断で書いたものも削除する。
5. 抽出した追加・変更コメントが `comment.md` の規律に違反している場合（複数段落の正当化、自明な what 言い換え、チャット文脈・移植経緯依存の記述、変更履歴的記述、冗長な FIXME / TODO 等）、Edit で簡潔化または削除する。手順 4 の根拠を満たす場合に限り FIXME 化してもよい。
   - 調整は形式上の違反のみを対象とする。当該コメントが対応する指摘（`{{document_path}}` の Finding を file:line と内容で対応付け）が要求する実質——特に Alternative 見積で方向性指定された FIXME の要点——は保持し、趣旨を棄損しない。規律順守と趣旨保持が両立しない場合は削除せず、簡潔化により要点を残す。
6. 戻り値を返す。

## 戻り値

`{reviewed_paths, fix_count, template_id}`

- `reviewed_paths`: 追加・変更コメントが検出されレビューしたファイルパス一覧（空配列もあり）
- `fix_count`: 修正したコメントの件数（手順 4 で削除した注記を含む。0 ならコメント修正なし）

`template_id` は本テンプレートの frontmatter から Read した値をそのまま含める。
