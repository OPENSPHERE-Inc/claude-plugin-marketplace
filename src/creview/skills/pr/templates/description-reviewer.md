プルリクエスト本文 — `{{pr_path}}` の `title` と `body` フィールド — を、`{{diff_path}}` の変更内容と `{{target_dir}}` 配下のコードに照らしてレビューする。`{{plugin_root}}/rules/sub-agent.md` を Read し共通禁止事項を遵守する。

確認観点:

- 整合性 — 本文が挙動・スコープ・互換性・設定・テストについて述べる主張が、すべてコードで成り立つ。
- 網羅性 — レビュアーや利用者が知るべきことを本文が扱っている: 利用者から見える挙動の変更、破壊的変更とその移行方法、新しい設定や依存関係、変更のテスト方法。
- 未解決事項 — 本文が未解決または未追跡のまま残している、未チェックのタスクリスト項目、TODO / TBD、未決の問い、既知の制限。

ルール:

- 使用ツールは Read / Glob / Grep / Bash(grep/ls/find) と、`{{output_path}}` への Write に限定。
- ロケーション: 差分が変更した行が本文の記述に反する挙動をする場合はそのコードの `file_path:line`。それ以外の指摘（変更行のどれも実装していない主張を含む）は `PR description`。
- 重要度ラベル: Critical（致命的・修正必須）/ Major（中リスク・修正すべき）/ Minor（注意事項）/ Info（参考）。`PR description` の指摘は、本文を書かれたとおりに信じた場合の害で格付けする: レビュアーや利用者を誤った判断に導くもの（コードが行わないチェック、記載のない破壊的変更）は Major、誰も誤らせない欠落は Minor、文言は Info。
- カテゴリラベル: `バグ` / `保守性` / `可読性` / `テスト` / `パフォーマンス` / `セキュリティ` / `スタイル` / `ドキュメント` / `設計` から 1 件以上、または `/` と `]` を含まない短い名詞句の新規ラベル。複数の場合は `/` 連結で 1 つの `[ ]` にまとめる。ラベルは `{{doc_lang}}` で記述する（プリセット名も `{{doc_lang}}` に訳す）。
- `{{plugin_root}}/rules/review.md` を Read して従う。

出力:

- `[重要度] [カテゴリ] ロケーション — 問題の説明とその重要性。` 形式の番号付きリストのみを `{{output_path}}` に Write する（前置き・後書きなし。指摘がなければ空ファイル）。`file_path:line` の行番号は対象ファイルを Read したときに表示される行番号とし、`{{diff_path}}` 内の位置は使わない。
- 説明は `{{doc_lang}}` で記述する。ロケーションと重要度ラベルはそのまま維持する。
- 戻り値: `{"path": "{{output_path}}", "critical": <int>, "major": <int>, "minor": <int>, "info": <int>, "template_id": "<このテンプレートの template_id>"}`
