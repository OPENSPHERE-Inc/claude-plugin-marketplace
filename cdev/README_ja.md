# cdev

*[English README](README.md)*

Claude Code 向けのチームネイティブなマルチエージェントコーディングワークフロー。単一
スキル `/cdev:coding` がエージェントチームを立ち上げ、タスクを設計から検証・レビュー
済みのコードまで駆動します。

## スキル

| コマンド | 目的 |
|---------|---------|
| `/cdev:coding` | コーディングタスクをエンドツーエンドで実装する。常駐チームを結成し、設計 → 設計レビュー → コーディング → QA → コードレビューをフィードバックループ付きで実行する。 |

タスク説明を添えて起動します。例: `/cdev:coding アップロードエンドポイントに
レートリミッタを追加`。

## ライフサイクル上の役割

`cdev` はマーケットプレースのライフサイクルの**実装ステージ**です。動作する自己点検済みの
初版を素早く作ることに最適化します。インループのレビューは**品質ゲート**であって権威ある
レビューではありません。権威あるレビューは後段の `creview`（`/creview:start` → `triage` →
`respond` → `resolve`）で実施してください。権威レビューを `creview` に委ねるため、`cdev`
は速度と一貫性に振っています。

## 仕組み

リーダー（チームリード）は `TeamCreate` でチームを作り、選定した各専門家を名前付きの
常駐 teammate として一度だけ spawn し、各 producer にレビュアーをペアリングして、2 つの
セルフェーズと最終 QA ゲートを駆動し、進捗をコンソールへ報告します:

1. **設計セル** — 各アーキテクトが担当領域の設計を書き、**ペアのレビュアー**がレビュー。
   アーキテクトが各指摘を **triage（修正 or 理由付きで却下）**、レビュアーが **resolve** して
   セルをクローズする。
2. **コードセル** — 各コーダーが自スコープを実装（テストスイートがあればテストファースト）。
   コメントがあれば `comment-sensei` がコメント違反を修正。**ペアのレビュアー**がレビューし、
   コーダーが triage、レビュアーが resolve してセルをクローズする。
3. **QA ゲート** — ビルド / フォーマット / テストを 1 回実行。失敗時は担当コーダーが修正し、
   その修正もレビューセルを通してから QA を再実行する（上限付きループ）。

セルは自律的に回ります: producer（アーキテクト / コーダー）とペアのレビュアーが
review ⇄ triage ⇄ resolve をレビュアーがクローズするまで反復します。リーダーはセルを設定し、
フェーズゲート（全設計セルがクローズしてからコーディング、全コードセルがクローズしてから
QA）を守らせ、QA ゲートを実行し、エスカレーションを裁定します。レビュアーと producer が
`Critical` 指摘でデッドロックした場合、レビュアーはリーダーへエスカレーションし、リーダーでも
裁決できなければユーザーに諮り `FIXME:` を残します。判断の優先順位は ①ユーザーの初期指示 →
②設計意図。権威あるレビューは `creview` なので、未解決はブロックせず `FIXME:` として残します。

teammate はフェーズをまたいで常駐するため、各自が文脈を保持し増分的に改訂します。
フィードバックは**ピア間**で流れ、リーダーはロスター・ペアリング・タスク状態・重要度
カウント・パス・QA 結果のみを保持し、本文は持ちません。

## 動作要件

このスキルはエージェントチームツール（`TeamCreate`、`SendMessage`、`TaskCreate` /
`TaskUpdate` / `TaskList`、`TeamDelete`）を使用し、それらが利用可能なランタイムでのみ
動作します。これは使い捨て・ステートレスなエージェント方式の広い移植性よりも効率を優先した、意図的な
トレードオフです。

## オプション

- `--review-rounds N`（既定 2）— セルごとの review ⇄ triage の最大反復回数。
- `--qa-attempts N`（既定 5）— QA 検証 ⇄ コーダー修正の最大試行回数。
- `--base {branch}`（既定 `main` / `master`）— 差分取得のベースブランチ。
- `--commit`（既定 off）— 検証済みの実装を 1 コミットでコミットする。

## アーキテクト / コーダー / レビュアーエージェント

このプラグインは専門のアーキテクト・コーダー・レビュアーを同梱しません。`team-analysis`
タスクが**移植先プロジェクト**（`.claude/agents/`）→**ユーザー**（`~/.claude/agents/`）→
**プラグイン同梱**の順に、サブディレクトリを含めて再帰的（`**/*.md`）にエージェントを列挙し、
各エージェントの frontmatter の `name` / `description` を読み、各ロールに最適なものを割り
当て（ロールごとに複数可）、それぞれを teammate として spawn します。あるロールに一致が
無い場合は `general-purpose` にフォールバックします。QA タスクもビルド / テスト修正の
専門家を同じ方法で解決します。

## 同梱エージェントとサポートファイル

- `agents/dev-helper.md` — 機械的な teammate。チーム結成（スコープ確定 + エージェント
  選定）と QA（プロジェクトのフォーマット / ビルド / テスト実行、失敗時の修正専門家の特定）
  を担う。
- `agents/comment-sensei.md` — コードコメントの専門家 teammate。コーディング中に追加・
  変更されたコメントを `rules/comment.md` に照らしてレビュー・修正する。
- `rules/` — `teammate.md`（teammate 共通ルール）、`agents-detection.md`、
  `build-format-detection.md`、`comment.md`、`review.md`、`document.md`。
- `scripts/` — `fetch-diff.sh`（QA / コードレビュー用の作業ツリー差分）、`rm-tmp.sh`
  （`.claude/tmp/` 配下の実行作業ディレクトリを削除）。スキルは
  `${CLAUDE_PLUGIN_ROOT}/scripts/...` 経由で呼び出し、teammate は変数 `{{plugin_root}}` で
  解決済みパスを受け取ります。

## ビルド / テスト検出

QA は `rules/build-format-detection.md` でプロジェクトのフォーマット / ビルド / テスト
コマンドを解決します。`build-format.md` 記述子（`.claude/rules/**/build-format.md`）を最
優先し、無ければ `CLAUDE.md`、次に `README.md` を参照します。いずれもワークフローを宣言
していない場合、QA は目視チェックのみを行い、`build-format.md` 記述子の追加を推奨する警告を
返します。

## 日本語マスタ（リポジトリ直下 `src/cdev/`）

日本語マスタはリポジトリ直下の `src/cdev/` にあり、本プラグインのツリーを 1 対 1 で
ミラーします（`src/cdev/skills/coding/SKILL.md` ↔ `cdev/skills/coding/SKILL.md` など）。
スキル名もプラグインと同一です。ここにある実稼働の英語ファイルは、そのマスタを翻訳して
生成されます。更新する際は `src/cdev/` 配下の日本語マスタを編集し、その後実稼働ファイルへ
パス書き換え（`${CLAUDE_PLUGIN_ROOT}` / `{{plugin_root}}`）を再適用します。
